# MeuTreino+ — Lacunas do MVP

Data: 22/10/2026. Base e evidências: MVP_FUNCTIONAL_INVENTORY.md. Diagnóstico; nenhuma correção implementada. P0 impede completar ou comprovar uma jornada essencial; P1 tem alternativa demonstrável; P2 pode aguardar. Complexidade é relativa, não prazo contratado.

## Cinco obstáculos principais

1. **Primeiro acesso e apresentação em aparelho sem comprovação integral.** Cadastro, login e perfil estão conectados, mas os testes obtêm o token por outbox. Instalação, URL de API acessível, SMTP real e abertura do link precisam de ensaio. É lacuna de validação/ambiente, não afirmação de backend ausente.
2. **Entrada fria offline interrompida.** Conta cacheada é recuperada pelo session-store, porém a raiz oferece apenas tentar novamente ou welcome. O layout privado permite offline; falta um caminho utilizável até ele.
3. **Foto real de equipamento ainda não comprovada.** Existe cadeia câmera→SQLite→API→arquivo privado→preview. Teste de assinatura PNG não prova fotografia ou renderização; permissões declaram uso apenas no perfil.
4. **Histórico não expõe todo o resultado.** Repetições e séries sem carga não aparecem integralmente no resumo, embora estejam persistidas.
5. **Conteúdo e demonstração de valor ainda superficiais.** Catálogo tem 12 movimentos integrados, mas instruções genéricas e nenhuma referência audiovisual entregue. Evolução longitudinal não existe. São P1: uma demonstração honesta pode usar texto revisado, treino e resumo, sem prometer vídeos/gráficos.

## O que reutilizar e o que não prometer

Manter catálogo/cache, CRUD de academias/equipamentos, montagem de ficha, registro de séries, snapshots e filas. O problema central não exige reescrever esses módulos. Ajustes propostos devem se concentrar em navegação, apresentação, conteúdo e validação do ambiente.

Usar kg, treino de força, descanso por exercício e um dispositivo no roteiro mínimo. Essas escolhas são limites explícitos da demonstração, não correções dos recursos pendentes. Não mostrar cobrança, agenda, vídeos, OAuth ou conflitos concorrentes como funcionalidades homologadas.

A conclusão dos P0 permite ensaiar o núcleo; não elimina riscos P1 nem substitui a revisão de segurança pausada. Aprovação de MVP demonstrável e prontidão de produção são decisões diferentes.

## Critério de saída

Um usuário de teste deve completar cadastro/login, perfil, catálogo, academia, equipamento com foto real, ficha, treino e histórico sem colar token obtido do banco, manipular fila ou executar SQL. Deve conseguir reabrir dados cacheados sem rede e, ao voltar, observar o estado confirmado de sincronização. Registrar aparelho/OS, versão do app, passos e evidências; repetir após encerramento do aplicativo. Nenhuma dessas homologações foi realizada nesta auditoria.
